# 운영팀 내부 업무 흐름

이 파일은 운영팀이 내부에서 확인해야 할 업무 흐름을 정리한다.

## 확인 우선순위

1. 사용자가 묻는 대상이 기업 고객인지 참여자인지 확인한다.
2. 운영 절차 질문인지 실제 데이터 조회 질문인지 분리한다.
3. 절차 질문이면 이 스킬의 레퍼런스를 사용한다.
4. 실제 현황, 숫자, 목록 질문이면 `search-data`로 조회한다.

## 관리자 업무 질문 처리

- "어디서 확인해?" 유형은 관리자 화면 또는 운영 절차가 정리된 경우에만 답한다.
- 정리된 기준이 없으면 화면 위치를 추측하지 않는다.
- 제품 동작과 관련된 질문은 `product-notes.md`도 함께 확인한다.

## 내부 시스템 접점 (확정)

- 참여자 평가 결과는 내부 관리자 시스템(**빅브라더**)에 입력한다. 미니인턴/빅브라더 관련 참여자 문의는 운영팀이 답변한다.
- 기업 측 화면은 **기업관리자페이지**(`recruitment.miniintern.com`)다. 기업정보 관리, 개최 신청, 최종결과물 검토, 기업 가이드가 여기에 있다.
- 기업관리자 등록 여부는 내부 실시간 업데이트 시트로 확인한다 (링크는 협업 시트 원본 참조).
- 기획안 제출 안내·리마인드 알림톡은 빅브라더에서 수동 발송한다 (2026년 1월 기준 자동화 미완).
- 기업 정보·기업관리자 정보는 빅브라더에서 운영팀이 직접 수정할 수 있다 (기업관리자페이지에 즉시 반영). 단, 관리자 정보를 '퇴사'로 바꾸면 되돌릴 수 없으니 신중히 처리한다.
- 챗봇 인계 문의는 빅브라더 > 유저 의견 > 문의 내역에서 처리한다 (`customer-support.md`의 처리 흐름 참조).
- 유저 대상 개별 컨택·CS 메일은 help 계정(회신 가능)으로 발송한다. **대량 메일을 발송하면 같은 계정의 다른 메일이 반송될 수 있으므로, 대량 발송 전에 운영팀에 사전 공유하고 분산 발송한다** (2025-05 결정).

## 유지보수(개발) 보드로 처리하는 반복 요청 유형

운영팀이 직접 처리할 수 없어 유지보수 작업 보드로 접수하는 요청 유형. 이런 문의가 오면 즉답하지 말고 보드 요청으로 처리한다.

- 기업관리자 마스터 권한 수동 승인 (마스터 퇴사 등)
- 기업명·사업자등록증 변경
- 공고 수동 마감, 구글 검색 비노출 요청
- 실운영하지 않은 개최 건(취소·유형 변경)의 데이터 삭제 — 참여자 데이터가 없는 경우에 한해 요청
- 계정 관련 특이 건 (소셜 연동, 탈퇴, 승계 검토)
- 수료증 발급 오류 확인

## 사업부 간 협업 (미니인턴 개최/운영 요청)

- 타 사업부의 개최·운영 요청은 협업 요청 보드의 '미니인턴 개최/운영 요청'으로 받는다. **희망 OT 일자 최소 8주 전** 접수가 기준이다.
- 요청 보드 기재 항목: 희망 직무, 진행 방식(온라인/오프라인·장소), 기타 특이사항(중간+최종피드백 여부 등), 희망 OT 일자, 개최 일자.
- 인스타그램·SNACK 홍보 콘텐츠도 협업 시트 요청 보드로 접수한다 (검토 중 수정 요청 가능, 업로드 일정은 내부 방침에 따라 조정될 수 있음. 인스타 규격 1080×1350px, 최대 10장 jpg).
- 운영 범위는 케이스별로 다르다. 개최만 지원(개최 + 자료 전달 + 피드백·평가 입력)부터, OT·수료평가 포함, 기업 섭외·과제 협의 포함, 홍보까지 전체 운영까지 단계적으로 나뉜다. 요청 부서와 R&R을 먼저 확정한다.
- 개최 유형·운영 범위별 수수료는 이 스킬에서 답하지 않는다. 협업 시트 원본과 담당자 확인으로 안내한다.

## 운영 업무 메모

- 원본 Notion export에는 개인 업무 기록과 회의록이 많다.
- 개인 기록은 확정 운영 기준이 아니므로 답변 근거로 쓰지 않는다.
- 회의록은 결정사항이 정제된 경우에만 사용한다.
